# 600 项首试数据字典

可携带版账本按冻结顺序保留 C、M、K 的所有首试终态。其长度、状态、时间值和摘要均来自既有记录。交付失败留空长度。0 仍是数值，仅在记录明确给出 0 时使用。

| 字段 | 含义与证据 |
|---|---|
| `slot` · `run_id` | 原 800 槽运行计划的槽号与唯一编号。EAX 的 200 个暂缓槽占原编号，本表只有三方法正式派发的 600 个槽。 |
| `map` · `stratum` · `dimension` · `instance_sha256` | 实例、四来源组、点数及原始使用的坐标字节摘要。来源组和摘要绑定冻结派发计划。 |
| `seed` · `method` | 同图配对种子和方法标识。M/K 的父池可按图、种子和方法臂登记关联。 |
| `status` · `failure_cause` | 原终态与失败原因注解。槽 12 保留 `execution_error`，原盘满对账给出 `disk_full`。槽 56 和 433 保留 `monitor_invalid`，监控总结记录持续分页压力。槽 408 也保留 `monitor_invalid`，原终态明确记录启动前可用内存低于 12 GiB。有效项不填原因。 |
| `checked_length` · `route_sha256` | 独立核验并计入质量比较的最终路线长度与路线字节摘要。两边均有有效长度才构成质量配对。 |
| `shared_paid_s` | 共同前段在本臂计入的累计费用，单位秒。有效 M/K 同池的共同费用各全额计入一次。C 从原坐标输入启动，已有记录以 0.0 标示父池费用。 |
| `last_external_gpx_verified_charged_s` | 旧派生列名 `selection_s`。取已保存 `gpx_calls` 最末条记录里的 `verified_s`，即该候选验环后相对于本臂计费原点的累计时刻，单位秒。对 K，该原点包含共同前段。空值表示该事件时间在原派生表没有记录。该字段是计时里程碑。算子净耗时需另据启动、结束与清理证据分解。 |
| `full_charge_s` · `delivery_s` | 完成封存时累计计费与认证提交最终路线时的累计计费，单位秒。对部分失败，原始完成证据提供了计费值。计费值本身不使失败可计分。 |
| `terminal_sha256` | 原有终态证据或槽 12 原盘满追加对账的摘要。 |

可携带版根据冻结计划补上 `slot`、`stratum`、`dimension`、`instance_sha256`，从已存失败回执增加 `failure_cause`，去掉仅在原机器成立的 `route` 路径，并为旧 `selection_s` 明确命名。原表、首试和计分规则仍按冻结记录保存。来源文件与副本摘要见 [frozen_reference.json](data/frozen_reference.json)。

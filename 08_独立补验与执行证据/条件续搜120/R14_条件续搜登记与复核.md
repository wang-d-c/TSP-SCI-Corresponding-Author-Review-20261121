# R14 条件续搜登记与复核

本批对三组由原 600 项极端反转选出的固定起点重复续搜。比较在相同续搜种子和 30 秒条件窗口下，两个固定起点分别达到的路线质量。原始父池和起始路线的生成支出在本批窗口外。

冻结时重新读取以上六个正式派发、终态及可认证完成凭据。独立核对原图、共同父池的时间费用封签、三条真实父环、六条起点环的完整长度、原 LKH first-trial 环与起点环的规范化一致性。续搜入口复用原 `phase_b_common_r3/methods.py::execute_mechanism` 及其被准入验证的二进制和资源监督模块。

## 冻结范围

- 每组父池使用同一组 20 个新续搜种子。种子在查看任何新结果前，由固定 SHA256 命名空间生成，规避旧主批次和旧条件批次已登记种子。
- 每组父池内 10 对 M 先和 10 对 K 先。用独立的 SHA256 顺序在固定种子间分配。同一种子两臂相邻运行，轮内三个父池的顺序预先冻结。
- 单核串行。采用原机制入口的 27.6 秒停搜请求、28 秒前停搜证明、29 秒前认证、30 秒前资源清理和完成时间界限。同一 LKH Windows 构建和预算。保留原 Windows Job 与 CPU0 亲和、CPU1 资源监测、4 GiB 单进程提交上限、12 GiB 起始和 8 GiB 运行可用内存限制、原 PDH 分页门槛。
- 合法容量内未交付作为真实终态保留。无法证实执行或共享链路出错则暂停。后续可在证据确认的资源恢复后续跑未派发项，既有结果和失败原样保留。
- 每组单独报告 20 对的完赛分布、全部差值、短/平/长、均值、中位数、范围、顺序分组和各臂失效。配对效应为 `10^6 × (M 终点长度 − K 终点长度) ÷ M 终点长度`。区间用每组有效配对的 10,000 次条件种子百分位重抽样，固定 RNG 种子与插值规则见报告程序。不把三个父池当成三个独立地图，也不把 120 次条件续搜并入主实验。

## 初次准入检查

原准入函数返回 `available physical memory below 12 GiB`。主机层非计时检查复核为 **10,778,710,016 字节可用（约 10.04 GiB）**，低于原 12 GiB 门槛。系统已接交流电，CPU0 与 CPU1 在许可范围。两项占用较高的 Python 进程属于用户的现有 VS Code 进程树。保持这些进程和原门槛。

此检查时 120 槽均未派发，资格验收未启动，未产生新续搜名次或统计区间。资源恢复后，先执行独立的针对性入口验收，再启动同一已冻结清单。

## 恢复和最终复核

经用户授权关闭 VS Code 后，以原门槛复查通过。先在 RUE-1500 的已有同池起点上验证两臂。两项均合法完成，未纳入 120 项种子诊断。实际从 2026-11-21 12:46:03 运行至 13:42:10（北京时间），120 项均通过证据链和路线检查，组成 60 对。停搜证明均在 27.613 至 27.639 秒，路线认证均在 27.648 至 27.691 秒，完成收费时间均在 27.733 至 28.037 秒。日志均通过内存及 PDH 检查，Job 清理均证实零活动进程。

最终报告在另一独立目录重算。120 槽 CSV、60 对 CSV 和条件统计 JSON 逐字节相同。结果图已生成并检查。
